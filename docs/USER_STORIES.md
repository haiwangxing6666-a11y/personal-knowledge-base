# 个人知识库用户故事

## 1. 文档目的

本文从使用者视角描述个人知识库的核心需求，并通过完整业务流程说明各模块之间的协作关系。

## 2. 目标用户

目标用户是需要集中保存、管理和检索个人资料的学生或开发者。

用户可能拥有分散的课程笔记、PDF、Markdown、Word 文档和网页收藏，希望通过自然语言快速找到其中的信息。

## 3. 核心用户故事

### US-01 上传文件

作为知识库用户，我希望上传 PDF、TXT、Markdown 和 DOCX 文件，以便统一保存和检索本地资料。

验收条件：

- 支持 PDF、TXT、Markdown 和 DOCX。
- 可以识别大写文件扩展名。
- 不支持的文件类型会返回明确错误。
- 文件内容为空时不会入库。
- 入库成功后可以在资料列表中看到该文件。

### US-02 创建笔记

作为知识库用户，我希望直接创建文本笔记，以便快速记录不属于文件或网页的知识。

验收条件：

- 笔记必须包含标题和正文。
- 空白笔记不能入库。
- 保存成功后可以在资料列表中看到笔记。
- 笔记内容能够参与知识库问答。

### US-03 收藏网页

作为知识库用户，我希望输入公开网页链接并提取正文，以便保存有价值的网络资料。

验收条件：

- 只允许 HTTP 和 HTTPS 地址。
- 能够提取网页标题和主要正文。
- 不允许访问本机或内网地址。
- 网页抓取失败时返回明确错误。
- 收藏成功后能够显示原始网页链接。

### US-04 管理资料

作为知识库用户，我希望查看、更新和删除已收录资料，以便保持知识库内容准确。

验收条件：

- 可以查看全部资料。
- 可以看到资料名称、类型、状态和文本块数量。
- 文件内容更新后，旧向量会被替换。
- 删除资料时，对应向量也会被删除。
- 已删除的内容不应继续影响问答结果。

### US-05 知识库问答

作为知识库用户，我希望使用自然语言提问，以便快速找到资料中的答案。

验收条件：

- 系统只根据已入库资料回答。
- 系统能够检索与问题相关的文本块。
- 首次检索依据不足时，可以改写问题并再次检索。
- 回答内容应尽量简洁、明确。

### US-06 查看回答来源

作为知识库用户，我希望看到答案引用的资料和原文片段，以便判断答案是否可信。

验收条件：

- 回答返回资料名称。
- 网页资料返回原始 URL。
- 回答返回命中的文本片段。
- 回答返回文本块序号和相似度。
- 关键结论应标注对应资料编号。

### US-07 无依据拒答

当知识库中没有相关资料时，我希望系统明确说明无法回答，而不是编造内容。

验收条件：

- 相似度过低的结果会被过滤。
- 两次检索都没有可靠依据时直接拒答。
- 拒答时不调用最终回答模型。
- 拒答响应中不包含虚假来源。

## 4. 用户故事串联

完整使用流程如下：

1. 用户上传文件、创建笔记或收藏网页。
2. 系统提取资料正文。
3. 系统将正文切分成带有重叠内容的文本块。
4. 系统生成文本向量并写入知识库。
5. 用户使用自然语言提出问题。
6. 系统执行第一次检索并过滤低质量结果。
7. 如果可靠依据不足，系统改写问题并执行第二次检索。
8. 系统根据可靠资料生成回答。
9. 前端展示回答、来源资料和原文片段。
10. 用户更新或删除资料后，系统同步更新向量数据。
11. 后续问答使用最新知识库内容。
12. 如果没有可靠依据，系统明确拒绝回答。

## 5. 当前范围

本版本包含：

- 文件、笔记和网页收录。
- 资料查询、更新和删除。
- 文本解析、切分和向量化。
- 基于知识库的问答。
- 查询改写和二次检索。
- 来源追踪和无依据拒答。
- Web 管理与问答页面。

本版本暂不包含：

- 用户注册和登录。
- 多用户数据隔离。
- OCR 和扫描 PDF。
- 图片、音频和视频解析。
- 文档版本历史。
- 公网部署和移动端应用。
